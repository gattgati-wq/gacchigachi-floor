- キャラ設定：すぎちゃんの決定に従う。※フロア上の人は、members.json の名前・名札がそのまま画面に出る（絵の割り当ては `floor/v3/img/README.md`・`floor/v4/README.md`）

## ルール
- **仕事をしたら、終わる前に、この説明書の「いまの状態」「判断待ち」を更新する**
- **状態ファイルは、仕事を始める時／待ちになった時／終わった時の3回だけ書く**（`floor/RULES.md`）。**自分のファイルだけ**。推測は書かない
- **仕事が出来上がったら、まなに連絡する**：まなのセッションへ直接メッセージ、または `floor/inbox/to-mana.md` に追記。**メールは使わない**。**1行目に「仕事完了」**、そのあとに、誰のデスクか・何が出来たか・判断待ちがあるか。急ぎ・判断が要るものは、要件の頭に書く。返事は不要
- **重い許可**（すぎちゃんの許可が要る）：**削除・公開・お金・外への送信**。**進捗の表示は、許可を挟まない**（開いた時に最新が見える形）
- **変更は、ドラフトPRまで**。**マージはすぎちゃん／みーの合図で**（フロア担当は、勝手にマージしない・「承認」しない）。**同じブランチには、PRが1つしか開けない**。**別PRにしたい時は、別ブランチ**を使う（このセッションは、**割り当てられた作業ブランチ以外へは、許可をもらってから** push した。環境の決まりで、新しい子も同じとは限らん）
- **このリポジトリは公開**。**鍵・パスワード・トークン・お客さんの情報・秘密のURL・アカウント番号・メールアドレスの値は、書かん**。`members.json` の `link` は **claude.ai のセッション／チャットのURL**（ログインが要るが、ID自体は公開される）。**新しく足す前に、みーに確認**
- **医療的な表現は使わない**（整体・治療院ではなく「痛快リラクゼーション」）
- 返事は**結論 → 状態 → 確認点**の順で短く。**質問は1つ**。**判断が要る事は「すぎちゃんの判断待ち」と明記**。すぎちゃんの文章を勝手に書き直さない

## 暗黙のルール（すぎちゃんの決定・好み）
- **余白があるほど美しい**。画面は「全部を詰め込む」方向にしない（すぎちゃんの言葉）。キャラは小さめ・余白広め
- **名札は、すぎちゃんの呼び方（持ち場＝名前）**。`members.json` の `title` に入れる（2026-11-24 の決定。例：アンプ・監査・LINE・待受）。個人名だけの名札は不親切、という考えが元
- **メンバーの色は、ボードのカード・名札・服で揃える**。親方は濃い赤 `#e53935`、まなは藍色 `#4356A6`（濃い色の上は白文字）。色の正本は、各画面の `COLORS`
- **止まった仕事は目立たせる**（やりっぱなし防止が、フロアの目的）。作業中・待ちが6時間更新なしで「止まってる」扱い（しきい値は定数。値は目安）
- 動きは**うるさくしない**。**「動きを減らす」設定では、必ず止める**
- **見た目の調整は、「数字1つで変えられる形」にして、確認点は1つ**で聞く（すぎちゃんは実機で見て決める。画面だけでは分からん）
- **曖昧な指示は、1つだけ聞く**（例：「✅の子を動かして」は、完了の子か作業中の子か。聞いたら「作業中」と確定）
- キキの絵は、**切れ端や欠けがあっても、すぎちゃんは「使う」と決めた**（画面側で安全に消せる分だけ消す。無理に消して絵を欠かさない）。「焦ってる」など届いてないポーズは、通常の絵で代用

- **他の子の状態ファイル**（本人だけが書く）
- **`members.json` の `id`**：状態ファイル名・絵のファイル名（`<ID>-<ポーズ>.webp`）・色・席と**全部つながっている**。変えると絵や色が外れる。名前（`name`）・名札（`title`）の変更は、ID は変えずに。**id と表示名が違う子がいる**：`ganechigamen`＝表示名「アンプ」、`bucho`＝「監査」、`chii`＝「ガチコ」（名札は「待受」）、`koukichi`＝「ガネチ」（名札は「予約システム」）。**ID で探して、表示名で探さない**
- **v3 / relay**：消さん・触らん（v3 は戻す時のため、relay は「置いておく」で決定済み）。v2 は不明（消す前にみーに確認）
- **画像のファイル名とキャラの席**：`<ID>-normal/busy/yawn/sleep.webp` など（v4）、v3 は `<ID>-normal/work/panic/yawn/sleep.webp`。**v3 と v4 でポーズ名が違う**ので混ぜない
- **`products.json`**：書くのは みー。ほかの子は書かない
- 画面は**GitHub の main のファイル**を読む：**mainに入るまで、画面には出ない**。**ブランチに置いただけでは、公開の画面は変わらない**

## 詰まりやすい所／やりがちな失敗
- **大きなファイルを、スクリプトで切り貼りして書き換える時**：**同じ見出しコメントが別の場所（CSSなど）にもあると、範囲がずれて壊れる**。目印は**一意なもの**を使い、書き換えたら**必ず構文を確認**する（`node --check`）。1箇所ずつ、**置換前の文字列がちょうど1つか**を確かめる
- **ファイルで開いた時は、埋め込みデータが出る**（古い）。最新を見るには、公開URL。埋め込みの更新：v4 は `python3 floor/v4/embed.py`（v3 は `floor/v3/embed.py`）。**更新前に、データが古いままの画面で判断しない**（v4 は、更新ボタンの下に、データの時刻が出る。埋め込みの時は「埋め込み＝古い可能性」と赤字で出る）
- **`<details>` は、フレックスの中で高さが伸びなかった**（このセッションの Chromium での観察。原因は未確認）。伸ばしたい時は、普通の `div` で作った
- **GitHub の通知**：PRを購読しておくと、CI・コメント・マージが届く。**「レビュー可」への変更は、すぎちゃん本人の操作**で来る。**勝手に合図と受け取らん**（マージの許可ではない）
- **同じ名前の別の子**：「フロア設計係」（チャット）と「フロア担当」（コード）。**どちらに渡す話か、取り違えない**
- 絵が**スマホで重くならん**ように：キャラ絵は画面用に小さく（約384〜512px・webp）してから置く（元の大きい絵は、そのまま置かん）

## 秘密まわり
- 鍵・パスワード・トークンは**持たない**・**書かない**。使用量の「トークン」は**使った量の数字**で、鍵ではない
- 中継役（Cloudflare Worker）は**使わない**。もし作ってしまった形跡があれば、**トークンを取り消して Worker を削除**するよう、みーに伝える（`floor/relay/README.md`）

## 動作確認のやり方
- **画面を実際に開いて見る**：コードのセッションには、ブラウザ（Chromium＋Playwright）が入っている。`file:///…/floor/v4/index.html` を開いて、**幅の違う2つ（PC・スマホ）でスクリーンショット**を撮る。**JSのエラーが無いこと**も見る
- **最新のデータを入れずに確かめたい時**：GitHub への読み込みを止めて（`raw.githubusercontent.com` へのリクエストを遮断）、埋め込みデータで開く。**仮の状態を一時的に入れて**、作業中・止まり・完了などの見え方を確かめる（**仮データは保存しない**）
- **動きの確認**：数字で測る（位置の変化など）。動画では見られないので、「実機で見てほしい」と書く
- **実機（すぎちゃんの端末）での確認は、すぎちゃん**。**自分で見たことと、見てないことを分けて報告する**
