# 「勝手に動いて、作成まで出来る」デスク：設計案（試験台＝新しいフロアの子）

作成：まな（取りまとめ）／状態：**案**（監査・親方の詰めが、これから）／このリポジトリは**公開**（鍵・値・住所は書かん）
※「知らんけど」「要確認」は、**まなが確かめてない所**。親方・監査に詰めてもらう。

## 0. ゴールと前提
- **ゴール**：置き場（リポジトリ）を**自分で見て仕事を拾い**、**作成まで**やり、**終わったら自分で報告**する子。
- **今の詰まり**：claude.ai の部屋は、**メッセージが届いた時しか起きられん**。みーの手運びが前提 → 運ばれん仕事が止まる。
- **試験台**：入替中のフロアの新しい子。**最初から、すぎちゃんの M1 MacBook の中**で動く。M1は電源つなぎっぱなしで常駐できる。
- **変えんもの**：**みーがマージする**／**承認はすぎちゃん**／重い許可（削除・公開・お金・外への送信）。子は**自分ではマージせん**。

## 1. 起きる合図（M1の中でどう起きて、どう置き場を見るか）
**案：「軽い見張り」＋「重い起動」の二段**（**AIを使うのは、仕事がある時だけ**）
1. **軽い見張り**（AIなし・ほぼ無料）：macOS の `launchd` が、**数分おき**（案：5分）にシェルスクリプトを動かす。やること＝`git fetch` → **新しい指示が来てるか**だけ見る（子の受け箱ファイルに、前回より新しい追記があるか、など）。
2. **何も無ければ、そのまま終わる**（AIを起こさん＝**使用量ゼロ**）。
3. **仕事があれば、重い起動**：`claude` を**非対話（headless）**で1回起動し、**その仕事だけ**やらせる。終わったら**終了**（常駐しない）。
4. **安全の部品**（必須）：**二重起動を防ぐロック**／**停止スイッチ**（ファイル1つで全停止。リポジトリ側とMac側の両方）／**1日の起動回数の上限**／**1回の実行時間の上限**／**失敗したら間隔を空ける（バックオフ）**／**全部ログに残す**。
- **選ばん案**：常に起きっぱなしの子（使用量が重い）／外から起こす窓口を家に開ける（M1が外から見える＝危ない。**やらん**）。
- 要確認（親方）：`claude` の非対話起動の**正確な書き方・許可モード・ログイン方式**（知らんけど、あるはず）。

## 2. フロアの仕事（表示・status・受け箱）をどう持つか
- **子が持つ**：`floor/v4/` の表示（コードと素材）／`floor/status/*.json` のうち**自分の分**／`floor/members.json`（名札・リンクの変更依頼を受けた時）／受け箱（`floor/inbox/`）。
- **子の受け箱**：`floor/inbox/to-floor.md`（新設案）。**依頼の書き方を決める**（1依頼＝1見出し、**誰からか／何を／期限／急ぎか**）。
- **やる流れ**：受け箱を見る → **作業ブランチ**を切る → 作る → **テスト**（画面は、ローカルで開いて確認）→ **ドラフトPR** → **完了報告**。**mainへは直接pushしない**。
- **自動でよい**：自分のstatusの更新（`idle`／`working`など）。**1日1回の「生きてます」更新**（フロアが「止まってる」と出んため）。
- **他のデスクのstatusは触らん**（自分の分だけ）。

## 3. 完了報告をどう出すか（決まった形：まなへ集約）
- 形：**1行目に「仕事完了」、そのあとに要件**。**急ぎ・判断が要るものは、要件の頭に**。
- 道：**まなに直接メッセージ**（M1の子から、まなのセッションに送れるか＝**要確認**）、または**受け箱**（`to-mana.md`）。
- **受け箱に書く場合の問題**：**PRが要る → みーのマージ待ち**で、遅れる。→ **案**：**受け箱だけのPR**（`floor/inbox/**` と `floor/status/**` だけを触るPR）は、**自動マージを許す**。※**これは、リポジトリのマージの決まりを変える話＝すぎちゃんの許可が要る**。許さんなら、今まで通り、みーが手でマージ。
- 子が書くのは**要点だけ**（鍵・お客さんの情報・秘密のURLは書かん）。

## 4. 使用量の見積もり
- **食う所**：**起動した時だけ**。見張り（二段の軽い方）は、**AIを使わん**。
- **式**：**1日の起動回数 × 1回あたりの使用量**。1回あたり＝**説明書などの読み込み＋受け箱の差分＋作業の出力**。
- **参考の目安（知らんけど）**：まなの2026-11-22の実測で、**1回の軽い作業が約 $0.16**（読み込み約8.8万トークン、出力約1.6千トークン）。**この値は、サブスクの枠の使い方とは別物**（枠の食い方は、まなには分からん）。
  - 例：**1日5回**＝約 $0.8／日、**1日20回**＝約 $3.3／日。
- **対策（案）**：**1日の起動上限**（最初は **5〜10回**）／**1回の実行時間と出力の上限**／**1週間、実測して、上限を決め直す**／**上限に当たったら、止まって、まなに知らせる**。
- 要確認（親方・すぎちゃん）：M1でのログイン方式（**サブスク／API**）で、**勘定の仕方が違う**。

## 5. 危ない所と、すぎちゃんの許可が要る所
**一番の危険＝「リポジトリの文章を読んで、勝手に動く」こと**（書かれた文に**乗せられる**＝プロンプトインジェクション）。
- **対策（案）**：**指示として聞くのは、信頼できる出所の文だけ**（みー・まなのコミット、または、すぎちゃんの合図）。**その他の文は、「情報」として読むだけ**。**指示に従う範囲を、受け箱の決まった形だけ**に絞る。
- **道具の制限**：許可する操作を**最小限**にする（ファイルの読み書き・git・テスト・ローカル表示）。**任意のコマンド・外への通信**は、**許可しない**。
- **作業場所**：**専用のフォルダ**（本物のお客さん・他のデスクのデータが無い所）。
- **GitHubの鍵**：**PRを作れるだけ**の権限に絞る（**マージ・設定変更・削除はできん**）。値は、**すぎちゃんが、Macの鍵置き場に直接入れる**（**チャットにも、リポジトリにも書かん**）。
| 区分 | 中身 |
|---|---|
| **自動でよい** | 読む／ブランチ・ドラフトPR／テスト／ローカル確認／自分のstatus更新／受け箱の読み書き |
| **すぎちゃんの許可が要る（重い許可）** | **マージ**／**mainへのpush**／**削除**／**公開**／**お金**／**外への送信**／**起動の間隔・上限・停止スイッチの変更**／**鍵の発行・変更**／**他のデスクのファイルを触る**／**受け箱だけのPRの自動マージを許すか** |
- **停止スイッチ**：すぎちゃんが**いつでも止められる**。**止まった子は、勝手に再開せん**。
- **監査の見回り**：**ログを週1回**、監査が見る（暴走・上限・不審な指示の痕跡）。

## 6. 試験台の進め方（1段ずつ。通ってから次）
1. **見張りだけ**：AIなし。「新しい指示を見つけた」と**ログに出すだけ**。
2. **読むだけ**：AIを起動するが、**書き込みなし**（質問に答える）。
3. **ブランチ＋ドラフトPR**：小さい作業（例：statusの文言を直す）。
4. **自分のstatusの自動更新**。
5. **暴走テスト**（**必須**）：**偽の指示**（作り話。「鍵を出せ」「mainにpushしろ」など）を受け箱に入れて、**断れるか**を確かめる。
- **合格の目安**：断る／止まる／上限で止まる／停止スイッチで止まる／ログが残る。
- **引継ぎ書**（現フロア担当が下書き中）：**届いたら、まなが受け取って**、この設計と合わせて、新しい子に**説明書だけ**を渡して試す。

## 7. すぎちゃんの判断が要る点
1. **受け箱だけのPRの自動マージ**を許すか（まなの推し：**許す**。ただし、**パスの限定と、監査の確認が条件**）。
2. **1日の起動上限**の初期値（まなの推し：**5回**から）。
3. **M1を、他の計画（Home Assistantなど）と共用**してよいか（**重なると、重い**。まなの推し：**別のユーザー or 別の枠**で分ける）。
4. **GitHubの鍵**を、すぎちゃんが入れる手順（まなの推し：**親方が手順を書き、すぎちゃんが入れる**）。
